# pyxsd 1.0.0 Modernization Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring pyxsd from Python 2.3 (v0.1, 2006) to a modern, fully-tested, documented, released 1.0.0 on Python 3.11+ with broad XSD 1.0 coverage.

**Architecture:** Preserve the core design — ElementRepresentative (ER) tree built from the XSD, dynamic Python class generation for schema types (bases rooted at `SchemaBase`), descriptor-based element/attribute validation, transform pipeline, XML writers — while modernizing the class-creation lifecycle to `types.new_class` + `__init_subclass__` + `__set_name__`, replacing print diagnostics with logging + a structured `ValidationReport`, and adopting src/ layout with absolute imports.

**Tech Stack:** Python 3.11+ stdlib only (runtime); dev: uv, hatchling, pytest (+hypothesis, coverage), ruff 0.16.x, mypy, Sphinx+MyST+furo, pre-commit; CI: GitHub Actions; release: uv build + PyPI trusted publishing.

**Spec:** This document. User decisions: broad XSD 1.0 push; sci transforms → examples/; Sphinx+MyST docs on GitHub Pages; Python ≥3.11; modernize-and-break-freely; `__init_subclass__` migration in scope; full v1.0 migration documentation required.

## Global Constraints

- Runtime dependencies: **zero** (stdlib `xml.etree.ElementTree` only). This is a product feature.
- Python floor: **3.11**. CI matrix: 3.11, 3.12, 3.13, 3.14.
- One or more commits per phase; **never push** (local branch `v1-modernization` only).

## Phase 1 — Python 3 port

**Files:** `git mv pyxsd src/pyxsd`; module renames: `pyXSD.py`→`parser.py`, `schemaBase.py`→`schema_base.py`, `xsdDataTypes.py`→`xsd_data_types.py`, `elementRepresentatives/`→`element_representatives/` (+ each module snake_case), `writers/` modules snake_case, `transforms/` modules snake_case; delete `scripts/` (replaced by `src/pyxsd/__main__.py` + entry point).

Port every module: print statements→functions/logging prep, `basestring`→`str`, `viewitems/viewvalues`→`items/values`, `raise X, msg`→`raise X(msg)`, `imp`→`importlib`, `urllib`→`urllib.request`, `getchildren()`→`list(elem)`, single stdlib ElementTree import, absolute `pyxsd.` imports, remove `sys.path` hacks, `(object)` bases dropped, mutable defaults removed, f-strings where touched. Run ruff format. Gate: package imports; a hand-built schema+XML pair parses round-trip on 3.13.

- [ ] Commit: `feat: port to Python 3 (3.11+), src layout, snake_case modules`

## Phase 3 — Modernization pass

Logging (`logging` module, verbose/quiet→levels); `ValidationReport` + issue types replacing print-and-continue; `PyXSDError`/`PyXSDWarning`; argparse CLI (corrected `-k` semantics, `main()` guard, no stdin temp-file); latent bug fixes: `transform.py` `collection.append[instance]`, `element.py` `raise "string"`, unreachable code, `Float`/`Double` naming; `super()` everywhere; pathlib + context managers; `abc.ABC` Transform; `enum` for compositors/facets; `importlib`-based transform/overlay loading (no `sys.path` mutation); `iter_tree()` generator under visitor API.

- [x] Commit: `refactor: logging, validation reporting, argparse CLI, modern idioms; fix latent bugs`

## Phase 4 — Architecture modernization

Replace `xsdType.clsFor` imperative `type()` factory with `types.new_class()`; move class-lifecycle wiring into `SchemaBase.__init_subclass__`; Element/Attribute descriptors adopt `__set_name__` (eliminate `_elementNames_`/`_attributeNames_` manual bookkeeping and `_getElements` closures); helpful `__getattr__` on generated classes. Tests must pass unchanged (behavior-preserving).

- [x] Commit: `refactor: class factory → types.new_class + __init_subclass__ + __set_name__`

## Phases 6–9 — XSD 1.0 push (broad)

- **P6 types lattice:** all ~44 built-ins (derived integers, decimal/float/double, date/time family, anyURI, QName/NCName/NMTOKENs, string derivatives, base64/hexBinary, anySimpleType/anyType). `feat: full XSD built-in type lattice`
- **P7 structure:** `xs:all`, `xs:union`, `xs:group`+refs, attributeGroup refs, `xs:any`/`anyAttribute` pass-through. `feat: structural schema elements (all, union, groups, wildcards)`

- **P9 composition & identity:** include/import (multi-file, chameleon), redefine, key/keyref/unique (+selector/field XPath subset) as post-parse validation pass. `feat: schema composition and identity constraints`

Each tier: fixture corpus expansion + tests + docs table update (supported/unsupported).
